## Коммиты

Сообщения коммитов пишутся **на русском языке** первая строка кратко, вторая строка пустая, третья и последующие описание более подробно, чтобы было понятно что сделано.

Каждое сообщение должно начинаться с префикса типа изменения:

| Префикс | Когда использовать |
|---|---|
| `feat:` | новая функциональность |
| `fix:` | исправление бага |
| `docs:` | изменения документации |
| `style:` | форматирование, отступы, clang-format (без изменения логики) |
| `refactor:` | рефакторинг без изменения поведения |
| `test:` | добавление или изменение тестов |
| `build:` | изменения системы сборки (CMake, зависимости) |
| `ci:` | изменения CI/CD |
| `chore:` | прочие служебные изменения |

Примеры:
```
feat: добавлена поддержка нескольких клиентов
fix: исправлена утечка файлового дескриптора при ошибке инициализации TUN
docs: добавлено описание формата зашифрованного пакета
build: добавлена зависимость libsodium
```

## Версионирование

После каждого коммита с изменением кода версия в `CMakeLists.txt` (формат `MAJOR.MINOR.PATCH.TWEAK`) продвигается отдельным коммитом `build: Версия X.Y.Z.0`.

Какую часть версии инкрементировать — определяется по префиксу предыдущего коммита:

| Префикс предыдущего коммита | Что инкрементировать |
|---|---|
| `feat:` | MINOR (Y), PATCH сбрасывается в 0 |
| `fix:`, `refactor:`, `style:`, `perf:` | PATCH (Z) |
| `docs:`, `test:`, `ci:`, `chore:` | версию не продвигать |

TWEAK (4-е число) не трогается, если явно не указано иное.
